# 콜리지 캐릭터 영역 + 아이템 영역

GitHub Pages용 정적 웹 프로젝트입니다.

## GitHub Pages 배포

저장소 루트에 `index.html`이 있어야 합니다.

GitHub → Settings → Pages → Build and deployment → Source에서 `Deploy from a branch`를 선택하고,
Branch는 `main`, Folder는 `/(root)`로 설정하세요.

이 프로젝트는 아래처럼 저장소 최상단에 `index.html`이 있어야 합니다.

```text
repository-root/
├─ index.html
├─ css/
├─ js/
├─ supabase/
└─ .nojekyll
```

GitHub Pages의 프로젝트 사이트 주소는 기본적으로 `https://<사용자명>.github.io/<저장소명>/` 형태입니다.

## Supabase

`js/config.js`에 Supabase Project URL과 Publishable Key가 설정되어 있습니다.
브라우저에 노출되는 키이므로 Supabase RLS 정책으로 쓰기 권한을 제한해야 합니다.

`supabase/schema.sql`을 Supabase SQL Editor에서 실행해 테이블과 RLS 정책을 생성하세요.


## Responsive layout

캐릭터 행과 아이템 행을 하나의 고정 비율 스테이지로 묶어 창의 가로/세로 형태에 따라 전체 크기만 비례 축소·확대합니다. 콜은 중앙 말풍선 영역의 왼쪽 안쪽 가장자리에, 엘리는 오른쪽 안쪽 가장자리에 붙고 아이템은 중앙 말풍선 영역 아래에 배치됩니다.

## 세계관(worldview)

모든 영역 가장 상단에 세계관 버튼 바가 있습니다. `≡ [][][][][] +` 구성입니다.

- 화면에는 항상 5칸만 보입니다. 이름이 비어 있는 칸은 비활성 상태입니다.
- `+` 로 이름을 넣으면 세계관이 추가되고 빈 칸이 하나씩 채워집니다.
- 5개를 넘겨도 계속 추가할 수 있고, 노출은 5칸 그대로입니다. 좌우로 드래그하면
  첫 버튼 왼쪽에 마지막 세계관이, 마지막 버튼 오른쪽에 첫 세계관이 이어지는
  무한 순환 스크롤로 넘겨볼 수 있습니다.
- 버튼은 하나만 선택됩니다. 선택된 버튼을 다시 누르면 해제됩니다.
- 전부 해제된 상태가 기본값이며, 이때는 모든 세계관의 대사·표정이 섞여 나옵니다.
  세계관을 지정하지 않고 등록한 항목(미분류)도 이 상태에서 보입니다.
- 전부 해제한 상태에서 대사를 말할 때는, 그 **대사가 속한 세계관**의 기본 이미지로
  말합니다. 중세 대사에는 중세 모습이, 학원 대사에는 학원 모습이 나옵니다.
  말풍선이 사라지면 원래 기본 이미지로 돌아갑니다.
- 세계관을 선택하면 캐릭터 기본 이미지가 그 세계관 설정으로 바뀌고,
  대사 목록(`≡`)과 표정 목록에도 해당 세계관 항목만 나옵니다.
  이 상태에서 새로 등록하는 대사·표정은 그 세계관에 저장됩니다.
- `≡` 는 세계관 목록입니다. 이름 수정, 삭제, 세계관별 기본 이미지 지정을 합니다.
  세계관을 삭제해도 대사·표정은 지워지지 않고 미분류로 남습니다.

선택한 세계관은 브라우저에 기억되어 새로고침해도 유지됩니다.

표정은 세계관에 속하므로 **세계관 목록(`≡`)의 '표정' 버튼**에서 관리합니다.
표정 목록 안에서 콜 / 엘리를 전환하고, 지금 선택된 세계관의 표정만 보입니다.

대사 목록의 각 줄은 대사 / 수정 / ✕ 로 단순합니다.
아이템·표정·세계관은 대사 **추가창과 수정창 안의 태그 버튼**으로 고릅니다.
추가창에서는 아이템·표정이 '기본', 세계관은 지금 고른 세계관이 기본값입니다.

같은 캐릭터, 같은 세계관 안에서는 같은 대사를 두 번 넣을 수 없습니다.
비교할 때 **띄어쓰기와 마침표만** 지우고 나머지 문장부호는 그대로 봅니다.

| 대사 | 비교 기준 |
| --- | --- |
| `...미안.` | `미안` |
| `미안.` | `미안` — 위와 같은 대사 |
| `미안!` | `미안!` — 다른 대사 |
| `미안?` | `미안?` — 또 다른 대사 |

마침표로 치는 글자는 `.` `．` `。` `…` `⋯` 입니다.
`js/ui.js`의 `PERIOD_LIKE`를 고치면 범위를 바꿀 수 있습니다.

대사 목록에는 제목 아래 한 줄에 아이템 · 표정 거르기와 정렬이 있습니다.

거르기 상자는 `아이템` / `표정` 이 전체(기본 상태)이고, 특정 아이템이나 표정을
고르면 그 대사만 남습니다. 켜져 있는 동안에는 상자가 캐릭터 색으로 표시됩니다.
선택지는 **지금 보이는 대사에 실제로 쓰인 것만** 담으므로, 골랐는데 아무것도
안 나오는 일이 없습니다. 쓰이지 않은 아이템이나 표정은 목록에 뜨지 않습니다.
(`js/modules/modals.js`의 `populateQuoteFilters`를 고치면 전부 보이게 할 수 있습니다.)

표정은 id가 아니라 **이름으로** 거릅니다. 표정은 세계관마다 따로 있어서
`미소`가 IF에도 크그에도 존재하는데, 이름이 같으면 한 항목으로 묶입니다.
세계관을 전부 해제한 상태에서 `미소`를 고르면 모든 세계관의 미소 대사가
함께 나옵니다.

거르기는 대사 목록을 열 때마다 전체로 되돌아갑니다.

정렬은 오래된순 / 가까운순 / 가나다순으로 바꿀 수 있습니다.
가나다순은 중복 판단과 달리 **문장부호를 전부 무시**합니다.
그래야 `...미안.` 이 마침표가 아니라 `ㅁ` 자리에 놓입니다.
선택한 정렬은 브라우저에 기억됩니다.
세계관 태그를 누르면 이미 등록된 대사를 다른 세계관으로 옮길 수 있습니다.
옮기는 세계관에 같은 이름의 표정이 있으면 자동으로 다시 연결하고,
없으면 물어본 뒤 표정을 해제합니다.

### 버튼 바가 흐르는 방식

버튼은 **다섯 칸**이 보이고, 평소에는 오른쪽에서 왼쪽으로 **초당 26px** 씩 천천히 흐릅니다.
가운데에 가까운 버튼일수록 커집니다. (가운데 1.0 → 한 칸 옆 약 0.81 → 두 칸 옆 0.62)

| 언제 | 어떻게 |
| --- | --- |
| 평소 | 저절로 흐름 |
| 세계관을 고름 | **멈춤.** 고른 것을 가만히 보라고 |
| 손이 닿아 있는 동안 | 저절로 미는 것을 멈추고 사용자에게 맡김 |
| 끌거나 민 직후 | 그 힘이 속도에 얹혔다가 1초 안에 원래 속도로 |
| 다른 탭에 가 있는 동안 | 멈춤 |

조절하는 값은 `js/modules/worldview.js` 맨 위에 모여 있습니다.
`DRIFT`(속도) · `FALLOFF`/`MIN_SCALE`(크기 변화) · `PUSH_*`(민 힘).

**크기는 칸(`.worldview-slot`)에 겁니다.** 버튼에 걸면 버튼의 hover 효과(`translateY`)와
서로 덮어씁니다. 또 폭을 실제로 바꾸지 않고 `transform` 만 건드려서,
매 프레임 배치를 다시 계산하지 않습니다.

**고른 세계관은 가운데로 옵니다.** 같은 버튼이 세 벌 깔려 있어서,
지금 화면 가운데에서 가장 가까운 한 벌을 골라 데려옵니다.
멀리 있는 것을 고르면 바가 화면을 가로질러 휙 지나갑니다.
데려가는 동안에는 민 여운이 끼어들지 않고, 손을 대면 즉시 그만둡니다.
첫 화면에서 지난번에 고른 것을 되살릴 때도 가운데로 옵니다.

**가운데로 데려갈 때도 정수 반올림을 조심해야 합니다.**
거의 다 와서 한 프레임에 1px 이 안 되게 움직이면 반올림에 먹혀 제자리에 머물고,
영영 '다 왔다'가 되지 않습니다. 남은 거리가 1px 이상이면 최소 1px 은 가게 합니다.

**감길 때는 목표 위치도 같이 옮깁니다.**
데려가는 도중에 목록이 한 바퀴 감기면 목표가 갑자기 한 벌만큼 멀어집니다.
그러면 그쪽으로 달려가다 또 경계를 넘어 또 감기고, 영원히 빙빙 돌게 됩니다.

**소수점 이하 거리는 따로 쌓아 둡니다.** `scrollLeft` 는 정수로만 저장돼서,
한 프레임에 0.43px 씩 더하면 매번 반올림되어 사라지고 영영 움직이지 않습니다.
1px 이 모일 때까지 `pending` 에 모았다가 한 번에 옮깁니다.

### 바 너비와 글자 크기

바는 `63.75% → 74%` 입니다. ≡ 를 글자 링크로 빼면서 바가 통째로 뷰포트가 되었고,
버튼을 한 단계 키웠습니다. **133×51px, 글자 22px** (그 전 109×42px, 17.95px 의 약 1.22배)

바 안쪽의 `cqw` 는 **바 자신의 너비**를 기준으로 합니다.
그래서 바를 넓히면 글자도 같이 커집니다. 그러지 않도록 `css/worldview.css` 안의
cqw 계수를 모두 `55/63.75 = 0.8627` 배로 줄여 두었습니다.
**바 너비를 바꾸면 그 계수도 같은 비율로 바꿔야 합니다.**

(바 자신의 `gap` 과 `margin-bottom` 은 바깥 기준이라 건드리지 않았습니다)

### 세계관 추가

메인 바에는 '+' 가 없습니다. **세계관 목록 창 맨 위**에 입력칸과 '추가' 단추가 있습니다.
넣으면 창이 닫히지 않고 그 자리에서 목록과 바에 바로 반영됩니다.

## 데이터베이스

처음부터 새로 만드는 경우 `supabase/schema.sql` 하나만 실행하면 됩니다.

이미 운영 중인 데이터베이스라면 SQL Editor에서 순서대로 실행하세요.

1. `supabase/worldview.sql` — 세계관 테이블 추가 (STEP 0에 백업 스냅샷 포함)
2. `supabase/optimize.sql` — 구조 간소화. **이 SQL을 먼저 실행한 뒤 코드를 배포하세요.**
3. 며칠 써보고 문제가 없으면 `optimize.sql`의 STEP 9(옛 컬럼 삭제)를 실행

`optimize.sql`이 정리하는 내용은 다음과 같습니다.

- `quotes.image` / `quotes.image_title` → `expression_id` 외래키 하나로 대체.
  같은 값을 두 테이블에 중복 저장하지 않으므로, 이를 맞춰주던
  `sync_expression_links` 트리거가 통째로 사라집니다.
  세계관마다 같은 이름의 표정을 둘 때 생기던 충돌 문제도 함께 없어집니다.
- `quotes.item_name`(한글 표시명) → `item_id`(고정 키).
  아이템 이름을 바꿔도 대사 연결이 끊기지 않습니다.
- 쓰이지 않는 인덱스 4개 제거. 앱은 전체를 한 번에 읽고 브라우저에서 거르므로
  WHERE 절이 없고, 조회용 인덱스는 쓰기 비용만 늘립니다.
  외래키를 받쳐주는 인덱스 3개만 남습니다.

STEP 9을 실행하기 전까지는 예전 코드로 되돌려도 그대로 동작합니다.

### SQL로 세계관을 한꺼번에 재분류한 뒤

대사는 `expression_id`로 표정을 정확히 가리킵니다. 그래서 대사만 다른 세계관으로
옮기면 표정은 옛 세계관 것을 계속 물고 있습니다.
앱의 세계관 태그로 옮길 때는 자동으로 맞춰주지만, SQL로 한꺼번에 옮긴 뒤에는
`supabase/realign.sql`을 실행해 주세요. 여러 번 실행해도 안전합니다.

어긋난 대사는 대사 목록에서 표정 태그가 **노란색**으로 표시됩니다.
눌러서 직접 다시 지정할 수도 있습니다.

## 아이템 끌어놓기

아이템을 캐릭터 쪽으로 끌어다 놓으면 그 아이템 대사를 말합니다.
탭(클릭)하면 아이템 설명창이 열립니다.

구현은 포인터 이벤트 기반입니다. HTML5 드래그앤드롭(`dragstart`/`drop`)은
모바일 브라우저가 터치로 발생시키지 않기 때문에 쓰지 않습니다.
`.item-btn`의 `touch-action: none`이 빠지면 손가락을 움직이는 순간
브라우저가 스크롤 제스처로 가져가면서 끌기가 끊기므로, 함께 두어야 합니다.

## 앱으로 설치하기 (PWA)

브라우저 주소를 몰라도 되도록, 홈 화면과 작업 표시줄에 아이콘으로 깔 수 있습니다.
별도의 앱스토어 등록이나 설치 파일은 필요 없습니다.

| 어디 | 어떻게 |
| --- | --- |
| 안드로이드 (크롬) | 주소창 오른쪽 **설치** 또는 메뉴 → **앱 설치** |
| 아이폰 (사파리) | 공유 버튼 → **홈 화면에 추가** |
| 윈도우 · 맥 (크롬/엣지) | 주소창 오른쪽 설치 아이콘 → **설치** |

설치하면 주소창 없는 자기 창으로 뜨고, 인터넷이 끊겨도 화면은 열립니다.
다만 대사·표정은 Supabase 에서 받아 오므로, 연결이 없으면 목록은 비어 있습니다.

관련 파일은 다음과 같습니다.

- `manifest.webmanifest` — 앱 이름 · 아이콘 · 창 모양
- `sw.js` — 서비스 워커. 껍데기를 저장하고 새 버전을 알립니다
- `js/modules/update.js` — 등록과 '새 버전이 있어요' 줄
- `css/update.css` — 그 줄의 모양
- `icons/` — 아이콘. `icon.svg` 를 고치고 `node icons/build-icons.mjs` 로 다시 만듭니다
  — 바탕은 비어 있고(투명) 말풍선 두 개만 남습니다. 바탕을 넣고 싶으면
  `icon.svg` 맨 앞에 `<rect width="512" height="512" fill="..."/>` 를 넣고 다시 만드세요

### 새 버전 내보내기

이미 설치된 앱에 알림이 뜨려면 **`sw.js` 의 `VERSION` 이 달라져야 합니다.**
이 파일의 내용이 바뀌어야 브라우저가 새 버전으로 알아봅니다.

```bash
npm run release     # sw.js 의 VERSION 을 오늘 날짜로 올립니다
git add -A && git commit -m "업데이트" && git push
```

올리고 나면 설치된 앱에서 이렇게 됩니다.

1. 앱을 다시 열거나, 켜 둔 채로 30분이 지나면 새 버전을 확인합니다
2. 화면 아래에 **새 버전이 있어요 [새로고침]** 이 뜹니다
3. 누르면 새 버전으로 다시 열립니다. ✕ 를 누르면 나중에 받습니다

쓰던 중에 갑자기 화면이 바뀌지 않도록, **누르기 전에는 그대로 둡니다.**

`npm run release` 를 잊지 않으려면 `.github/workflows/deploy.yml` 을 쓰세요.
올릴 때마다 커밋 번호로 버전을 자동으로 찍습니다.
쓰려면 저장소 **Settings → Pages → Source** 를 `GitHub Actions` 로 바꿔야 합니다.
안 쓸 거면 그 파일을 지우면 됩니다.

### 캐시를 어떻게 다루는지

서비스 워커는 **늘 인터넷을 먼저 봅니다.** 저장해 둔 것은 인터넷이 안 될 때만 씁니다.
반대로 하면 코드를 고쳐 올려도 예전 화면이 계속 나옵니다.

GitHub Pages 는 파일을 10분쯤 캐시하므로, 올린 직후엔 최대 10분 늦게 보일 수 있습니다.

## 항상 위에 띄우기 (컴퓨터 전용)

왼쪽 위 **압정 단추**를 누르면 작은 창으로 떨어져 나와 다른 창들 위에 계속 떠 있습니다.
다른 일을 하면서 콜과 엘리를 띄워 둘 수 있습니다.

브라우저에서 창을 '항상 위'로 고정하는 방법은 **Document Picture-in-Picture** 하나뿐입니다.
원래 영상용으로 만들어졌지만 안에 아무 화면이나 넣을 수 있습니다.

| 어디 | 되나 |
| --- | --- |
| 크롬 · 엣지 (컴퓨터) | ○ |
| 파이어폭스 · 사파리 | ✕ |
| 휴대폰 · 태블릿 | ✕ (이 API 자체가 없습니다) |

**안 되는 브라우저에서는 단추가 아예 만들어지지 않습니다.** 눌러도 안 되는 단추를
띄워 두지 않으려는 것입니다.

### 어떻게 만들었는지

작은 창 안에는 이 앱을 **`?pip=1` 로 한 벌 더 띄웁니다.**
화면 조각만 옮겨 담는 방법도 있지만, 그러면 아이템 끌어놓기의 좌표 계산과
`document.getElementById` 가 원래 창을 가리켜 어긋납니다. 통째로 띄우면 그냥 똑같이 돕니다.

`?pip=1` 이 붙으면 이렇게 달라집니다.

- 커서 캐릭터 · 업데이트 알림 · 압정 단추를 켜지 않습니다 (`js/app.js` 의 `EMBEDDED`)
- 커서 캐릭터와 압정은 CSS 로도 숨깁니다 (`html.is-embedded`, `css/ontop.css`)
  — 그리기 전에 `index.html` 맨 위에서 표시를 붙이므로 깜빡이지 않습니다

**노래는 작은 창이 맡습니다.** 작은 창에도 음악바가 그대로 뜹니다.
대신 원래 창의 노래는 떼어 낼 때 멈추고(`pauseMusic()`), 바도 감춥니다
(`body.is-popped-out .music-player`). 두 창에서 같은 노래가 겹쳐 나오면 안 되니까요.

작은 창이 떠 있는 동안 원래 창은 접어 둡니다. 같은 화면이 두 군데 떠 있으면 헷갈리니까요.

**돌아올 때는 원래 창을 다시 읽어 옵니다.** 작은 창은 별개의 한 벌이라,
거기서 대사를 추가해도 원래 창은 모르고 있기 때문입니다.

## 음악바

오른쪽 위에 있습니다. 코드는 `js/modules/player.js`, 모양은 `css/player.css` 입니다.

- 스피커에 마우스를 올리면 **세로 음량바**가 아래로 펼쳐집니다. 아래가 0%, 위가 100%입니다.
- 브라우저는 사람이 건드리기 전에는 소리를 못 냅니다. 그래서 첫 움직임(`mousemove`·
  `pointerdown`·`keydown`·`touchstart`)을 기다렸다가 그때 틀어 봅니다.
- 그 기다림은 **재생바 안을 누른 것이면 건너뜁니다.** 누르면 `pointerdown` 이 먼저,
  `click` 이 뒤따라 오는데, 앞의 것이 노래를 틀어 버리면 뒤의 것이 '이미 나오는 중'으로 보고
  도로 멈춰서 첫 누름이 아무 일도 안 한 것처럼 보이기 때문입니다.

## 효과음

캐릭터를 누를 때와, **아이템을 끌어다 놓을 때** 말풍선이 뜨면서 '뽁' 소리가 납니다.
다섯 가지 중 하나가 무작위로 나옵니다.

| | |
| --- | --- |
| 소리 파일 | `sfx/pop-1.mp3` ~ `sfx/pop-5.mp3` (0.47 ~ 1.06초, 합쳐서 71KB) |
| 코드 | `js/modules/sfx.js` |
| 부르는 곳 | `js/modules/characters.js` 의 `activate`, `js/modules/items.js` 의 `onPointerUp` |

**≡ · + 단추를 누를 때는 나지 않습니다.**

소리를 바꾸려면 `sfx/` 안의 파일을 갈아 끼우면 됩니다.
개수를 늘리거나 줄이려면 `js/modules/sfx.js` 맨 위 `POPS` 목록을 고치세요.
(서비스 워커가 미리 받는 `sw.js` 의 목록도 같이 고쳐야 오프라인에서 납니다)

크기는 같은 파일의 `VOLUME` (0 ~ 1) 로 조절합니다. 지금은 0.7 입니다.

### 음량을 맞춰 둔 이유

받은 다섯 파일의 원래 음량이 제각각이었습니다.
그대로 두면 무작위로 나올 때마다 크기가 널뛰어서 거슬립니다.
그래서 **평균 음량을 모두 -25dB 로 맞춰** 두었습니다.

| 파일 | 원래 (Freesound) | 원래 평균 | 조정 |
| --- | --- | --- | --- |
| `pop-1.mp3` | gamestudio, popup show #384945 | -30.2dB | **+5.2dB** |
| `pop-2.mp3` | u_1h808mpion, pop sound effect #505213 | -24.8dB | -0.2dB |
| `pop-3.mp3` | floraphonic, happy pop 1 #185286 | -23.9dB | -1.1dB |
| `pop-4.mp3` | universfield, bubble pop #293342 | -24.6dB | -0.4dB |
| `pop-5.mp3` | dragon studio, pop #402323 | -26.2dB | +1.2dB |

올린 뒤에도 최대 음량이 0dB 를 넘지 않게 해서 소리가 깨지지 않습니다.
새 파일을 넣을 때 그것만 유난히 크거나 작으면 다시 튑니다.

### 같은 소리가 연달아 나지 않습니다

다섯 개뿐이라 순수한 무작위로 두면 같은 소리가 연속으로 나오는 일이 꽤 잦고,
그러면 '무작위'로 느껴지지 않습니다. 그래서 **바로 앞에 났던 것은 빼고** 고릅니다.
(40번 눌러 본 결과: 6~9번씩 고르게 나오고, 연속 중복 0회)

> 다섯 소리 모두 Freesound 에서 받은 것입니다.
> Freesound 는 소리마다 사용 조건이 달라서, **CC-BY** 인 경우 공개 사이트에
> 만든 사람 이름을 적어야 합니다. 위 표의 원본 페이지에서 한 번씩 확인해 주세요.

## 왼쪽 위 단추들

한 줄에 나란히 섭니다. 자리와 간격은 `css/controls.css` 의 `.top-controls` 가 잡습니다.

| 단추 | 하는 일 | 처음 값 | 파일 |
| --- | --- | --- | --- |
| 압정 | 항상 위에 뜨는 작은 창으로 띄우기 | — | `js/modules/ontop.js` |
| 효과음 | '뽁' 소리를 낼지 말지 | **켜짐** | `js/modules/controls.js` |
| AUTO | 누르지 않아도 캐릭터가 알아서 말하기 | **꺼짐** | `js/modules/controls.js` |

압정은 크롬·엣지(컴퓨터)에서만 만들어지고, `js/modules/ontop.js` 가 이 줄 맨 앞에 끼워 넣습니다.
없는 브라우저에서는 효과음부터 시작합니다.

**새로고침하면 다시 이 기본값으로 돌아옵니다.** 켠 상태를 기억하게 할 수도 있지만,
창을 열자마자 혼자 떠들기 시작하면 놀랄 수 있어서 그러지 않았습니다.
기억하게 하려면 `js/modules/controls.js` 에서 `localStorage` 에 담으면 됩니다.

### AUTO

켜면 **0.6초 뒤에 한 번** 말하고, 그 다음부터는 **5 ~ 12초 사이에서 무작위로** 쉽니다.
말풍선이 8초 떠 있으니 둘이 겹치기도 하고 비기도 하면서 자연스럽게 이어집니다.
말하는 캐릭터도 매번 무작위로 고릅니다.

간격은 `js/modules/controls.js` 맨 위 `MIN_GAP` · `MAX_GAP` 로 조절합니다.

**AUTO 로 나온 대사에는 소리가 나지 않습니다.** 클릭으로 나온 게 아니니까요.
하트도 뜨지 않습니다. 둘 다 클릭 처리 쪽에만 붙어 있어서,
AUTO 는 `speakRandomQuote()` 를 좌표 없이 부르는 것만으로 자연스럽게 빠집니다.

다른 탭에 가 있는 동안에는 말하지 않고 넘어갑니다.

### 작은 창에서도

효과음과 AUTO 는 '항상 위에 띄운 작은 창' 안에서도 그대로 씁니다.
오히려 거기서 더 쓸모가 있어서요 — 띄워 두고 AUTO 를 켜면 알아서 떠듭니다.
(압정만 거기서 빠집니다. 이미 그 창이니까요)


## 위쪽 목록 링크

바 위에 **세계관 목록 | 표정 목록** 글자만 있습니다. 마우스를 올리면 그 단어에 밑줄이 쳐집니다.
예전의 ≡ 아이콘과 세계관 목록창 안의 '표정' 단추를 대신합니다.

밑줄은 `text-decoration-color` 를 투명 ↔ 색으로 바꿔서 냅니다.
`border-bottom` 으로 하면 밑줄이 자리를 차지해서 올릴 때마다 줄이 흔들립니다.

## '수정' 단추 모양

세계관 · 대사 · 표정 목록의 **수정** 단추는 평소에 **테두리와 글자에만 색**이 있고
배경은 비어 있습니다. 마우스를 올리면 색이 꽉 찹니다.
**'추가' · '등록' 단추는 예전 그대로** 꽉 찬 모양입니다.

엘리 대사 목록에서는 엘리 색(`#3E6B75`)으로 바뀝니다.

### 고른 세계관은 마우스를 올려도 그대로

`.worldview-btn:hover` 가 `.worldview-btn.is-active` 보다 구체적이라,
고른 버튼에 마우스를 올리면 안 고른 것처럼 하얘지던 문제가 있었습니다.
고르면 그 버튼이 가운데(=커서가 있던 자리)로 오기 때문에 특히 잘 보입니다.
`.worldview-btn.is-active:hover` 를 더해 막았습니다.

## AUTO 를 켜면

- 켜자마자 **두 사람이 모두** 말합니다
- 말풍선은 **사라지지 않습니다.** 내용만 갈아끼워집니다
- 갈아끼우는 때는 캐릭터마다 따로, 5~12초 사이 무작위라 둘이 엇갈립니다
- 끄면 지금 떠 있는 것부터 평소대로 8초 뒤 사라집니다

말풍선을 붙잡아 두는 건 `js/modules/characters.js` 의 `setBubblesHeld()` 입니다.
켜져 있는 동안 사라짐 예약을 걸지 않습니다.

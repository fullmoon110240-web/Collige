# 콜리지 캐릭터 영역 + 아이템 영역

GitHub Pages용 정적 웹 프로젝트입니다.

## GitHub Pages 배포

저장소 루트에 `index.html`이 있어야 합니다.

GitHub → Settings → Pages → Build and deployment → Source에서 `Deploy from a branch`를 선택하고,
Branch는 `main`, Folder는 `/(root)`로 설정하세요.

이 프로젝트는 아래처럼 저장소 최상단에 `index.html`이 있어야 합니다.

```text
repository-root/
├─ index.html
├─ css/
├─ js/
├─ supabase/
└─ .nojekyll
```

GitHub Pages의 프로젝트 사이트 주소는 기본적으로 `https://<사용자명>.github.io/<저장소명>/` 형태입니다.

## Supabase

`js/config.js`에 Supabase Project URL과 Publishable Key가 설정되어 있습니다.
브라우저에 노출되는 키이므로 Supabase RLS 정책으로 쓰기 권한을 제한해야 합니다.

`supabase/schema.sql`을 Supabase SQL Editor에서 실행해 테이블과 RLS 정책을 생성하세요.


## Responsive layout

캐릭터 행과 아이템 행을 하나의 고정 비율 스테이지로 묶어 창의 가로/세로 형태에 따라 전체 크기만 비례 축소·확대합니다. 콜은 중앙 말풍선 영역의 왼쪽 안쪽 가장자리에, 엘리는 오른쪽 안쪽 가장자리에 붙고 아이템은 중앙 말풍선 영역 아래에 배치됩니다.

## 세계관(worldview)

모든 영역 가장 상단에 세계관 버튼 바가 있습니다. `≡ [][][][][] +` 구성입니다.

- 화면에는 항상 5칸만 보입니다. 이름이 비어 있는 칸은 비활성 상태입니다.
- `+` 로 이름을 넣으면 세계관이 추가되고 빈 칸이 하나씩 채워집니다.
- 5개를 넘겨도 계속 추가할 수 있고, 노출은 5칸 그대로입니다. 좌우로 드래그하면
  첫 버튼 왼쪽에 마지막 세계관이, 마지막 버튼 오른쪽에 첫 세계관이 이어지는
  무한 순환 스크롤로 넘겨볼 수 있습니다.
- 버튼은 하나만 선택됩니다. 선택된 버튼을 다시 누르면 해제됩니다.
- 전부 해제된 상태가 기본값이며, 이때는 모든 세계관의 대사·표정이 섞여 나옵니다.
  세계관을 지정하지 않고 등록한 항목(미분류)도 이 상태에서 보입니다.
- 전부 해제한 상태에서 대사를 말할 때는, 그 **대사가 속한 세계관**의 기본 이미지로
  말합니다. 중세 대사에는 중세 모습이, 학원 대사에는 학원 모습이 나옵니다.
  말풍선이 사라지면 원래 기본 이미지로 돌아갑니다.
- 세계관을 선택하면 캐릭터 기본 이미지가 그 세계관 설정으로 바뀌고,
  대사 목록(`≡`)과 표정 목록에도 해당 세계관 항목만 나옵니다.
  이 상태에서 새로 등록하는 대사·표정은 그 세계관에 저장됩니다.
- `≡` 는 세계관 목록입니다. 이름 수정, 삭제, 세계관별 기본 이미지 지정을 합니다.
  세계관을 삭제해도 대사·표정은 지워지지 않고 미분류로 남습니다.

선택한 세계관은 브라우저에 기억되어 새로고침해도 유지됩니다.

표정은 세계관에 속하므로 **세계관 목록(`≡`)의 '표정' 버튼**에서 관리합니다.
표정 목록 안에서 콜 / 엘리를 전환하고, 지금 선택된 세계관의 표정만 보입니다.

대사 목록의 각 줄은 대사 / 수정 / ✕ 로 단순합니다.
아이템·표정·세계관은 **수정 버튼을 눌러 대사 수정창 안에서** 바꿉니다.
세계관 태그를 누르면 이미 등록된 대사를 다른 세계관으로 옮길 수 있습니다.
옮기는 세계관에 같은 이름의 표정이 있으면 자동으로 다시 연결하고,
없으면 물어본 뒤 표정을 해제합니다.

## 데이터베이스

처음부터 새로 만드는 경우 `supabase/schema.sql` 하나만 실행하면 됩니다.

이미 운영 중인 데이터베이스라면 SQL Editor에서 순서대로 실행하세요.

1. `supabase/worldview.sql` — 세계관 테이블 추가 (STEP 0에 백업 스냅샷 포함)
2. `supabase/optimize.sql` — 구조 간소화. **이 SQL을 먼저 실행한 뒤 코드를 배포하세요.**
3. 며칠 써보고 문제가 없으면 `optimize.sql`의 STEP 9(옛 컬럼 삭제)를 실행

`optimize.sql`이 정리하는 내용은 다음과 같습니다.

- `quotes.image` / `quotes.image_title` → `expression_id` 외래키 하나로 대체.
  같은 값을 두 테이블에 중복 저장하지 않으므로, 이를 맞춰주던
  `sync_expression_links` 트리거가 통째로 사라집니다.
  세계관마다 같은 이름의 표정을 둘 때 생기던 충돌 문제도 함께 없어집니다.
- `quotes.item_name`(한글 표시명) → `item_id`(고정 키).
  아이템 이름을 바꿔도 대사 연결이 끊기지 않습니다.
- 쓰이지 않는 인덱스 4개 제거. 앱은 전체를 한 번에 읽고 브라우저에서 거르므로
  WHERE 절이 없고, 조회용 인덱스는 쓰기 비용만 늘립니다.
  외래키를 받쳐주는 인덱스 3개만 남습니다.

STEP 9을 실행하기 전까지는 예전 코드로 되돌려도 그대로 동작합니다.

### SQL로 세계관을 한꺼번에 재분류한 뒤

대사는 `expression_id`로 표정을 정확히 가리킵니다. 그래서 대사만 다른 세계관으로
옮기면 표정은 옛 세계관 것을 계속 물고 있습니다.
앱의 세계관 태그로 옮길 때는 자동으로 맞춰주지만, SQL로 한꺼번에 옮긴 뒤에는
`supabase/realign.sql`을 실행해 주세요. 여러 번 실행해도 안전합니다.

어긋난 대사는 대사 목록에서 표정 태그가 **노란색**으로 표시됩니다.
눌러서 직접 다시 지정할 수도 있습니다.

## 아이템 끌어놓기

아이템을 캐릭터 쪽으로 끌어다 놓으면 그 아이템 대사를 말합니다.
탭(클릭)하면 아이템 설명창이 열립니다.

구현은 포인터 이벤트 기반입니다. HTML5 드래그앤드롭(`dragstart`/`drop`)은
모바일 브라우저가 터치로 발생시키지 않기 때문에 쓰지 않습니다.
`.item-btn`의 `touch-action: none`이 빠지면 손가락을 움직이는 순간
브라우저가 스크롤 제스처로 가져가면서 끌기가 끊기므로, 함께 두어야 합니다.
